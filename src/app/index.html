        2. Choose shares

        Tick the shares to move and choose where each one goes on this server. Then check the plan: it measures each share and checks free space and permissions. Nothing is copied yet.

        Puts each selected share in its own folder inside the folder you choose. Or use Browse on a share. New folders are created when copying starts.

        3. Copy

        Users can keep working on the old server while you copy. Each copy after the first brings over only what changed, so copy again as often as you like.

        Copies files, folders, timestamps and NTFS permissions with Robocopy. Files removed from the old share are also removed from the copy.

        4. Cut over

        Ask users to stop using the old shares first. Cutover makes a final copy, creates the shares on this server with the old share settings and permissions, and compares the old and new files.

              Every copy, whether from Move VMs, Replicate servers or Send here, goes to a receiver on the new machine. On a Hyper-V host or any Windows computer, start Receive here: each disk is saved as a VHDX file. A new HyperCore, Nutanix, Proxmox or physical machine boots receiver media instead and writes each disk straight onto its own disks. Send copies the disks of the computer it runs on by hand, for one machine without the replication agent; sending again later sends only what changed. To keep servers in sync until a scheduled cutover, use Replicate servers; to move a VMware or Hyper-V VM with nothing installed in it, use Move VMs.

                Start a VM from the copies

                A test failover starts a VM on new differencing disks whose parents are the copies, so nothing the test VM writes reaches the copies. Replication pauses for those copies while the test runs (the source keeps running) and catches up by itself when you end the test. Leave the network not connected, or choose an isolated switch, so the test VM never meets the real server on the network. Use production after the job's cutover: the VM runs from the copies themselves and they stay held.

                        Replicate whole servers
                        Install the replication agent on the servers you are moving, physical or virtual, then keep every disk copied to the new machine until you cut over. Each round sends only what changed, so the copy stays a few minutes behind. Jobs keep running on the servers when this window is closed.

                        Install the agent on the servers you are copying

                        Only the source servers get the agent. The new machines run a receiver instead: Receive on a Hyper-V host or other Windows computer, or receiver media on a new HyperCore, Nutanix, Proxmox or physical machine.

                        Runs on this computer and installs the agent as a Windows service on each server through its administrative share. You need administrator rights there and File and Printer Sharing allowed. To install it by hand instead, run SIMM-Agent.exe --agent-install as administrator on the server and add it below.

                        Runs on this computer and installs the agent as a systemd service on each server over SSH, using simm-agent-linux-amd64 from the folder this program is in (download it from the same release). Use root or an account that may use sudo. The first time, the server's SSH key is shown so you can check and trust it. Logical volumes on LVM are copied from LVM snapshots; other mounted partitions are copied as they are. To install by hand, run sudo ./simm-agent-linux-amd64 --agent-install on the server and add it below.

                          Alerts
                          
              
                          A job raises an alert when its recovery point is older than its RPO limit, when three rounds fail in a row, or when a cutover is rolled back. Agents also write them to the server's Application event log (source SIMM Replication Agent, events 1001 to 1003) for your monitoring tools.

                            Test failover on the target platform
                            
              
                            For copies received by receiver media in a VM on Scale Computing HyperCore, Nutanix AHV or Proxmox VE. Runs from this computer: the job pauses when its current round ends, the platform clones the receiver VM (the clone gets its own disks) and replication resumes at once. The clone's network is disconnected, it is set to start from its disk and started. Ending the test turns the clone off and deletes it; the receiver VM and its disks are never changed.
                            
              
                            
              
                            
                
                            
                
                            
                
                
                            
              
                            
              
                            
              
              
                            
              
                              
              
                              
              
                              
            
                              
            
                              Cut over
                              
            
                              Cutover stops the listed services, takes the last snapshots, sends the last changes and checks every disk against its hashes. If any step fails, the services start again and replication carries on. Start the new machine once the job says Cut over.
