## Primary application baseline

- Maintain the Windows portable executable, Server-Inventory-Configuration-Manager.exe.
- The user-confirmed functional and visual baseline is Server Inventory & Configuration Exporter GUI v3.0.10.
- The original source ZIP's bundled EXE is byte-identical to the uploaded baseline. See docs/verification/baseline-verification.json.
- The v3.1.0 PS1 application was a mistaken product direction. It is historical only. Never use its UI, collector extraction, or build workflow as the executable baseline.
- v3.2.0 introduced executable updates. v3.2.1 restored direct original-source build inputs and hardened the updater. Maintain v3.2.10 or newer, including locked-target cleanup, guest browser isolation and profile-scoped shutdown.
- Public source and releases: https://github.com/TechSavage1989/Server-Inventory-Configuration-Manager
- Public executable feed: https://github.com/TechSavage1989/Server-Inventory-Configuration-Manager/releases/latest/download/update-manifest.json
- Target Windows x64; Go 1.20.14 retains the broad Windows Server 2012+ target. Older Windows versions still require field validation.

Phase 3 targets (2026-11-25, user-requested: HyperCore, Nutanix AHV, Proxmox VE and physical servers): the new VM or server boots receiver media and receives the copy straight onto its own disks. `vmcopy_raw.go` is the raw disk sink (`vmRawSink`, a `vmCopySink`): it writes only a blank disk (first and last megabyte zero), a disk whose record is in the records folder, or a disk the operator listed with `--overwrite-disks`; records live in a records folder keyed by the disk's identity (`vmRawRecordPath`), never on the disk. Zero chunks are skipped only where the disk is known to read zeros. When overwriting a larger disk, its last megabyte is cleared so a stale GPT backup cannot survive. `vmcopy_raw_windows.go` opens `\\.\PhysicalDriveN`, always refuses the disks holding Windows, this program or the records, and takes the target offline (not persistently) before writing; never write to an online disk with mounted volumes. The receiver (`startVMReceiverWith`) serves VHDX files in its folder and/or its listed disks named `disk-N`; it never opens a disk it was not started with. `--receiver` (`vmreceiver_cli_windows.go`) runs it without the window for boot media; the pairing code is printed to the console only, never to `receiver.log`. `TestRawCopyOntoAWindowsDiskMatchesTheSource` writes a real attached disk. Receiver media (`Build-ReceiverMedia.ps1`, embedded, PowerShell 3.0 compatible, run by `vmBuildReceiverMedia`) uses the operator's own Windows ADK and Windows PE add-on (never ship or download Windows PE), adds drivers from folders the operator chose, places the EXE in `X:\Receiver` and starts `--receiver --disks blank` with `start /wait`. It refuses an existing ISO, a non-empty work folder and any disk list other than `blank` or numbers, checks everything before mounting, and discards the mounted image on failure. `--disks blank` takes every blank, unprotected disk. The receiver command keeps output that is already redirected (pipes, files) and attaches a console only otherwise. Native feel (2026-11-26, owner: "make sure the browser right click context menu is blocked and irrelevant ui elements cannot be selected"). `body` is `user-select:none`; values stay selectable through one opt-in rule in `index.html` (inputs, textareas, `pre`, `code`, `td`, `dd`, `.log-view`, `.vm-mono`, `.selectable` and the path/value classes), and buttons, labels, summaries, `th` and tabs are never selectable. Mark any new copyable value with one of those or `.selectable`. `blockBrowserMenu` cancels the `contextmenu` event (on the page and the loaded report) unless it is in a text field or on text the person selected, so Copy and Paste still work there; the app adds no key handlers for it. The built-in window keeps default context menus on for those cases and turns browser accelerator keys off (`PutAreBrowserAcceleratorKeysEnabled(false)`: no Find, Print, Reload or Save page); the keys still reach the page, so the app's own shortcuts work.
