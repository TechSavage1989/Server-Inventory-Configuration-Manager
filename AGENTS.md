## Primary application baseline

- Maintain the Windows portable executable, Server-Inventory-Configuration-Manager.exe.
- The user-confirmed functional and visual baseline is Server Inventory & Configuration Exporter GUI v3.0.10.
- The original source ZIP's bundled EXE is byte-identical to the uploaded baseline. See docs/verification/baseline-verification.json.
- The v3.1.0 PS1 application was a mistaken product direction. It is historical only. Never use its UI, collector extraction, or build workflow as the executable baseline.
- v3.2.0 introduced executable updates. v3.2.1 restored direct original-source build inputs and hardened the updater. Maintain v3.2.10 or newer, including locked-target cleanup, guest browser isolation and profile-scoped shutdown.
- Public source and releases: https://github.com/TechSavage1989/Server-Inventory-Configuration-Manager
- Public executable feed: https://github.com/TechSavage1989/Server-Inventory-Configuration-Manager/releases/latest/download/update-manifest.json
- Target Windows x64; Go 1.20.14 retains the broad Windows Server 2012+ target. Older Windows versions still require field validation.

## Development rules

1. Preserve the original layout, collectors, reporting, report viewer, scope controls, and icon unless the user requests a change. Run scripts/verify_baseline.py. Keep the original hashes in docs/verification/baseline-verification.json unchanged. For user-approved collector or icon changes, record the compared revision separately and update the verifier/tests without relabeling changed bytes as the original baseline. The user-approved HTML redesign replaces only Write-ConsolidatedHtmlReport. Its canonical template/CSS/JS are in reporting; scripts/embed_report_renderer.py embeds them into the self-contained collector. The original renderer is archived under baseline/v3.0.10/reports and current hashes are in docs/verification/report-verification.json. The baseline verifier restores that exact original function before checking the original whole-script hash, so all collectors, Word/text generation, block creation and raw exports remain protected. Original icon bytes now live in baseline/v3.0.10/icons. The original user-approved Illustrator master is src/app/assets/icons/source/server-inventory-illustrator.svg (preserve exact bytes and editor payload); scripts/prepare_icon.py derives src/app/assets/icons/server-inventory.svg without external DTDs or active content. Both source hashes and active hashes are in docs/verification/icon-verification.json.
2. Update appVersion, collectorVersion, and the original standalone collector's scriptVersion consistently. Source files are committed directly; do not extract them from legacy PS1 applications.
3. Link the approved SVG-derived icon and Windows file/product version metadata during compilation with scripts/build_resources.py. Do not patch a compiled EXE.
4. Keep the portable filename stable. Install in place to preserve existing shortcuts, including legacy custom/versioned names. Do not rename a user's executable or shortcut silently.
5. Settings, updater logs/cache/downloads/health/rollback, and browser session files belong under per-user LocalAppData/Server Inventory Configuration Manager. The one transient replacement file on the executable's volume is removed after replacement or failure.
6. Startup checks follow the authenticated first UI paint. Native timers schedule checks every five minutes; focus checks require two minutes. Keep single-flight, ETags, cooldown, Retry-After, GitHub reset handling, and persistent backoff. Cached/offline/failed checks never mean up to date.
7. Never automatically download, install, or restart. Block installation during collection, report loading, or folder dialogs. Prevent new critical operations once installation starts.
8. Validate HTTPS/redirect hosts, exact repository and version paths, size, SHA-256, PE sections/entrypoint/architecture/subsystem, mapped application identity marker, and Windows version metadata before execution. The manifest hash is byte validation, not a publisher signature.
9. The downloaded application is its own native helper. Stage on the target volume, retain exactly one previous rollback EXE, and require token/PID/path-matched health with a rendered UI and visible owned window. Never ship a headless healthy-start bypass.
10. Launch the interface only in an app-owned guest browser profile with extensions and sync disabled. Never fall back to a personal profile or change user/system browser policies. Respect policies that block guest mode or require account sign-in. Discover and close the exact app-owned profile even when Edge hands off to another PID; never kill browsers by name. Quiesce UI requests before install/shutdown and show update-action errors inline. When no guest window can open (policy-blocked or no browser), show the interface in the built-in WebView2 window (`src/app/webview_windows.go`, data folder `Runtime/WebView2`); it is a fallback, not a replacement, and never uses a browser profile or changes policy. Build only with the default WebView2 loader: never the `native_webview2loader` tag, which loads the loader DLL from memory and is the kind of behaviour endpoint protection flags. WebView2 component errors exit the process unless intercepted, so keep the host's error callback. `TestExecutableUsesBuiltInWindowWhenGuestBrowsingIsBlocked` covers the fallback with a real per-user policy. Allow `webViewStartTimeout` (3 minutes) for the first start: a new WebView2 Runtime (157 on hosted runners) can take over 45 seconds to embed, and a shorter limit showed a false "could not open" box while the window finished loading. A host that starts after the limit closes itself instead of loading the interface.
11. Persist native window bounds/maximized state in Settings/window.json, separately from inventory settings and disposable guest profiles. Use GetWindowPlacement/SetWindowPlacement consistently, preserve the last non-minimized state, constrain restored bounds to available monitor work areas, and flush before closing the browser or starting the update helper. Keep per-thread DPI handling isolated from existing dialogs. The real-EXE window test must cover native close/reopen, maximize, minimized close, normal restore bounds, invalid state, off-screen recovery and unchanged inventory settings.
12. Compile the approved ICO into the EXE. Refresh only application shell items through SHChangeNotify after the first authenticated paint and after native install/rollback replacement. Current-user desktop shortcut icons use persistent content-addressed ICO files under LocalAppData/Server Inventory Configuration Manager/Icons. Public-desktop and portable-folder links use the EXE icon so they remain portable across users. Modify only links whose exact target matches the running EXE; preserve target, arguments, working directory, description, hotkey and window state. Use native COM on a locked STA thread without Resolve, PowerShell, UI prompts, cache deletion or Explorer restart. Leave unrelated links and old icon files still referenced by shortcuts intact. Native tests must compare actual shell-rendered EXE/shortcut pixels and reproduce the stale old-icon reference. The published upgrade must repair an actual current-user desktop shortcut and preserve its launch properties.
13. Keep credentials, tokens, private signing keys, and customer data out of source and artifacts. Do not add server setup, Codex CLI automation, unattended workers, payment setup, or API-account setup.

24. The 2026-11-12 file share migration (Migrate tab) is user-requested: live copy from the old server, run on the new server, every share except administrative shares (system shares listed but unticked), and all optional after-cutover steps offered. `src/app/Migrate-FileShares.ps1` (PowerShell 3.0 compatible) and `src/app/migrate.go` implement it. Keep Robocopy `/MIR` from ever running into a destination that holds files the migration did not create (checked in both Precheck and Sync), keep copies repeatable and resumable from `Migrations\<source>\state.json`, and parse Robocopy summaries by row/column position because its labels are localized. The old server is changed only by the explicit read-only step, which saves permissions first so Undo restores them. The old-name alias (`netdom computername /add`) is offered only when the old name no longer answers and this server is domain-joined with netdom present, and needs a typed confirmation. Every step is a critical operation that blocks collection, restore, update install and closing. `scripts/Test-Migration.ps1` (CI job `migration`) runs a real round trip with the runner as both servers. The optional Connect as account (2026-11-18, user-requested) reaches the engine only as one JSON line on standard input (`-CredentialFromInput`), never on a command line, in state.json, the state response (user name only), logs or settings; Go holds it in memory for the current source until Start over or exit. The engine uses it for CIM (`-Credential`) and for files through a run-scoped `WNetAddConnection2` connection to `\\<old>\IPC$`, removed when the run ends. Access-denied failures emit an `accessDenied` event so the tab opens the account fields. The migration test covers it with a synthetic local administrator on the runner and checks that no output file contains the password. New folders (2026-11-20, user-requested): `/api/migrate/browse` opens the native folder picker (a folder dialog, so it is a critical operation and refused while a step runs) for one share or a parent for all; `migrateProtectedFolder` refuses Windows, Program Files, ProgramData and profile folders. Robocopy copies the top folder's own ACL but its inherited entries then follow the new parent, so `Set-RootPermissions` gives the new top folder the old one's effective ACL (inherited entries included, generic rights mapped) as a protected list after each successful copy (Robocopy rewrites it whenever the top folder changed), only when it differs. It writes with `SetFileSecurity`, which does not propagate: the .NET/PowerShell setters re-apply inheritance through the whole tree, which made the next Robocopy pass recopy every file. Cutover opens `\\<this server>\<share>` and marks the share for attention if it does not open. The 2026-11-21 user-requested override is per share and defaults off: `allowOverwrite` lets an administrator deliberately mirror into a previously occupied destination and replace an existing SMB share name during cutover. Preserve the fail-closed empty-folder and name-collision checks unless this flag is set or the tool owns the prior sync/share. Copy with overwrite requires typing the destination server's name, even on repeat delta passes; cutover retains its existing typed confirmation. Robocopy /MIR is destructive: explain that destination-only files will be deleted and no automatic file backup exists. Before replacing an existing share definition or permissions, save its old path, settings and share ACL to the local migration work folder. A failed recreate must attempt to restore the original mapping and permissions. Never allow overwriting ADMIN$, IPC$ or drive administrative shares, or silently replace a clustered/scoped share. SYSVOL, NETLOGON and other role-managed shares remain unticked and display extra warnings if manually selected; their replacement can interrupt domain/Windows services. Run actual Windows migration overwrite and backup round trips and UI confirmation tests before publishing.
