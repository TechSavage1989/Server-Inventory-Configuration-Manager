## Primary application baseline

- Maintain the Windows portable executable, Server-Inventory-Configuration-Manager.exe.
- The user-confirmed functional and visual baseline is Server Inventory & Configuration Exporter GUI v3.0.10.
- The original source ZIP's bundled EXE is byte-identical to the uploaded baseline. See docs/verification/baseline-verification.json.
- The v3.1.0 PS1 application was a mistaken product direction. It is historical only. Never use its UI, collector extraction, or build workflow as the executable baseline.
- v3.2.0 introduced executable updates. v3.2.1 restored direct original-source build inputs and hardened the updater. Maintain v3.2.10 or newer, including locked-target cleanup, guest browser isolation and profile-scoped shutdown.
- Public source and releases: https://github.com/TechSavage1989/Server-Inventory-Configuration-Manager
- Public executable feed: https://github.com/TechSavage1989/Server-Inventory-Configuration-Manager/releases/latest/download/update-manifest.json
- Target Windows x64; Go 1.20.14 retains the broad Windows Server 2012+ target. Older Windows versions still require field validation.

It never overwrites a file it did not create or a copy of a different source. Sources are local flat VMDKs or raw images and datastore files read over the vSphere `/folder` HTTPS interface with GET/HEAD Range requests only; snapshot deltas, sparse/SEsparse disks and RDMs are refused with the reason (conversion is phase 4). Encrypted VMs must be decrypted before any copy. The Receive and send disks tool (`#vmViewDisks`, `vmware_disks*.go`) starts and stops this computer's receiver and sends this computer's disks through the agent; the receiver's optional firewall rule uses one fixed rule name, is the only rule it touches, and is removed when the receiver stops or the application closes; sending needs administrator rights and is refused while this computer is receiving; Send can target a raw receiver's `disk-N` through `vmAgentTargetNames` (Check receiver asks `/api/vmware/agent/receiverdisks`), compress chunks with deflate (`enc=deflate`; the receiver inflates with a size limit and still checks each chunk's SHA-256) and pace them with `vmThrottle` (`repl_throttle.go`, business-hours schedule in Mbps); a receiver open with `rescan` rebuilds the copy record from the target's content in the background (`vmRescanHashes`, polled through `/v1/rescan`) so a copy onto a disk that changed or already holds the data (after a test failover, or a failback) sends only chunks that differ; disk names come from `vmAgentDiskName` so repeat sends are delta passes; the pairing code is shown in the receiver panel but never logged or saved unsealed. Every field where a mask is typed accepts either form (`parseIPv4WithMask` in Go, `ipMaskParse`/`ipPrefixOf` in the page: `10.0.0.11/24`, `10.0.0.11/255.255.255.0`, `10.0.0.11 255.255.255.0`, `10.0.0.11 mask 255.255.255.0` or the shown form) and refuses a mask whose bits are not contiguous; Build Hyper-V hosts' address fields (`hbInput` with `ipMask`) show the dotted mask and save address/prefix, and Move a domain controller's spare-address field is **Subnet mask**. Hyper-V inventories pair each guest address with its mask from `Msvm_GuestNetworkAdapterConfiguration.Subnets` (`hypervAddressList`). Use these helpers for any new address display or mask field; `netmask_test.go` and the workspace check "join an existing cluster" cover them.
