Read this file and DEVELOPMENT_HANDOFF.md before making changes.

## Primary application baseline

- Maintain the Windows portable executable, Server-Inventory-Configuration-Manager.exe.
- The user-confirmed functional and visual baseline is Server Inventory & Configuration Exporter GUI v3.0.10.
- The original source ZIP's bundled EXE is byte-identical to the uploaded baseline. See docs/verification/baseline-verification.json.
- The v3.1.0 PS1 application was a mistaken product direction. It is historical only. Never use its UI, collector extraction, or build workflow as the executable baseline.
- v3.2.0 introduced executable updates. v3.2.1 restored direct original-source build inputs and hardened the updater. Maintain v3.2.10 or newer, including locked-target cleanup, guest browser isolation and profile-scoped shutdown.
- Public source and releases: https://github.com/TechSavage1989/Server-Inventory-Configuration-Manager
- Public executable feed: https://github.com/TechSavage1989/Server-Inventory-Configuration-Manager/releases/latest/download/update-manifest.json
- Target Windows x64; Go 1.20.14 retains the broad Windows Server 2012+ target. Older Windows versions still require field validation.

## Development rules

6. Startup checks follow the authenticated first UI paint. Native timers schedule checks every five minutes; focus checks require two minutes. Keep single-flight, ETags, cooldown, Retry-After, GitHub reset handling, and persistent backoff. Cached/offline/failed checks never mean up to date.
7. Never automatically download, install, or restart. Block installation during collection, report loading, or folder dialogs. Prevent new critical operations once installation starts.

9. The downloaded application is its own native helper. Stage on the target volume, retain exactly one previous rollback EXE, and require token/PID/path-matched health with a rendered UI and visible owned window. Never ship a headless healthy-start bypass.
10. Launch the interface only in an app-owned guest browser profile with extensions and sync disabled. Never fall back to a personal profile or change user/system browser policies. Respect policies that block guest mode or require account sign-in. Discover and close the exact app-owned profile even when Edge hands off to another PID; never kill browsers by name. Build only with the default WebView2 loader: never the `native_webview2loader` tag, which loads the loader DLL from memory and is the kind of behaviour endpoint protection flags. WebView2 component errors exit the process unless intercepted, so keep the host's error callback. `TestExecutableUsesBuiltInWindowWhenGuestBrowsingIsBlocked` covers the fallback with a real per-user policy.

Use GetWindowPlacement/SetWindowPlacement consistently, preserve the last non-minimized state, constrain restored bounds to available monitor work areas, and flush before closing the browser or starting the update helper. Keep per-thread DPI handling isolated from existing dialogs. The real-EXE window test must cover native close/reopen, maximize, minimized close, normal restore bounds, invalid state, off-screen recovery and unchanged inventory settings.

## Repository standards (all contributors and AI tools)

This repository follows the shared TechSavage1989 standard in [`docs/REPOSITORY_STANDARDS.md`](docs/REPOSITORY_STANDARDS.md), the same file in every app repository. Read it before changing anything. In short:

- **README:** centered header (real icon, one `<h1>`, tagline, quick links Download · Get started · Features · Screenshots · Updates · Development, hero image), then the standard section order. Update it in the same pull request as any user-visible change.
- **Screenshots:** real captures with fictional data in `docs/images/` (`hero.png` + kebab-case names). Recapture any screenshot a UI change makes stale, in the same pull request.
- **Layout:** compact root; respect the root allowlist and checks above. Never commit build output, binaries, archives, logs, caches or secrets.
- **Branches:** short-lived `feat/` `fix/` `docs/` `chore/` `release/` branches, one focused change per pull request, merge only on green checks, delete the branch after merging.
- **Instructions:** this file is the single source of project rules for every tool; `CLAUDE.md` imports it. Add new rules and gotchas here.

The update feed and in-app update banner show the first three `- ` bullets of `docs/release-notes/<version>.md` verbatim as plain text, so keep those three bullets free of Markdown emphasis or code formatting.

README application screenshots in `docs/images/` are captured from the real `src/app/index.html` with the production CSP and synthetic `/api/state` responses at 1440 px wide (1000 px tall unless the existing image is shorter). The interface switches to its compact layout (no hero/version row, no update notes) at 720 px of height or less, so use at least 760 px when those should show. `report-executive-summary.png` is the published release's `Report-Preview.png` (real renderer, synthetic data); refresh it after each release that changes the report.

18. The update bar (`#updateBanner`) is visible only while an update exists (available, downloading, ready or installing). Routine results (up to date, checking, offline, paused) and the manual check (`#updateCheckButton`) live in Help > About and updates. Do not reintroduce an always-visible update status. Connection-lost messages use the application notice, not the update bar.
19. Low resolution is a requirement, not a nicety: the workspace must stay reachable and legible in the viewport left by 800x600 and 1024x768 screens (about 784x522 and 1008x690). `scripts/test_workspace.cjs` enforces this, including a 10.5 px minimum text size. Shrink chrome before working areas, and let a panel scroll rather than clip. The last Edge/Chrome for Windows Server 2012 and 2012 R2 is version 109: do not use CSS or JavaScript features newer than that in `src/app/index.html` or `reporting/`.
20. The backend is never the foreground process (the guest browser is), so Windows refuses a plain SetForegroundWindow. Shell opens call `allowForegroundHandoff` first and folder opens raise the new Explorer window through `forceWindowToFront`. Keep both when changing `/api/open`.

Where this file's project-specific rules differ from the shared standard, this file wins; an enforced check script wins over both.
