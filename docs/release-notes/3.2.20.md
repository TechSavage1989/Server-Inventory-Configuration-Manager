# Server Inventory and Migration Manager 3.2.20

Migration release. The application is now called Server Inventory and Migration Manager and adds a file server migration tool. Collection, reports, restore, update validation and settings are unchanged.

**Highlights**

- New Migrate tab: move file shares from an old server to this one in four steps: connect, choose shares, copy, cut over.
- Copies files, folders, timestamps and NTFS permissions while users keep working, then creates the shares here with the old share settings and permissions and checks that nothing differs.
- The application is renamed Server Inventory and Migration Manager; your executable, settings and shortcuts stay as they are and updates continue.

**Details**

- Run the application as administrator on the new server and type the old server's name. Every share except administrative shares is listed; system shares such as NETLOGON are shown but not ticked.
- Check plan measures each share and checks the new folder, free space and permissions that name accounts which won't exist here. Copy again as often as you like: each pass copies only what changed and removes what was deleted on the old server. A copy never runs into a folder that already holds other files.
- Cut over asks you to type this server's name, makes a final copy, creates the shares and compares old and new folders.
- After cutover you can make the old shares read-only (with Undo), list DFS links that point at the old server, and, once the old server is retired, give this server the old server's name so mapped drives keep working.
- Logs and the saved plan live under %LOCALAPPDATA%\Server Inventory Configuration Manager\Migrations, so a migration can continue after the application is closed. The executable keeps its file name, and Windows still lists Server Inventory Configuration Manager as the product name, so existing copies keep updating.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime. Migration and restore need administrator rights, on both servers for migration.
- A matching SHA-256 is integrity validation, not publisher signing.
- Migration was validated with a real round trip on hosted Windows Server 2025 using one machine as both servers. Copies between two separate servers, domain environments (DFS links and taking over the old server name), Windows Server 2012 sources and very large shares have not been validated; try a test pair first.
