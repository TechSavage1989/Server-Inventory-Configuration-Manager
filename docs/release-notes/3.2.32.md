# Server Inventory and Migration Manager 3.2.32

Migration release. The VMware tab can now copy and move VMs itself: to Hyper-V on the host you run it on, and to Scale Computing HyperCore, Nutanix AHV, Proxmox VE or a physical server through receiver boot media. A new Disk converter tab converts between disk formats, Hyper-V hosts can be read as a source, and any Windows machine can send its own disks to another computer. Collection, reports, restore, file share migration, update validation and settings are otherwise unchanged.

**Highlights**

- Move to Hyper-V: copy a running VMware VM's disks to VHDX files on the Hyper-V host, copy again for only what changed, then cut over to a new Hyper-V VM built from the VMware settings.
- Move to HyperCore, Nutanix AHV, Proxmox VE or a physical server: the new VM or server boots receiver media built from your Windows ADK and the copy is written straight onto its disks.
- Disk converter tab and Disk copy view: convert between VMDK, VHDX, VHD, qcow2 and raw, read a Hyper-V host as a source, and send a running Windows machine's disks to another computer.

**Details**

- Copies use VMware changed block tracking and this application's own temporary snapshot, which is removed after every round. The first copy reads only the used areas, and every copy can be stopped and resumed.
- Cut over shuts the guest down through VMware Tools, never with a forced power-off, copies the last changes, checks every disk against its recorded hashes and creates the new VM. The VMware VM is left powered off and otherwise unchanged, so going back is starting it again.
- Hyper-V VMs get generation 2 with Secure Boot and a virtual TPM where the VMware VM used EFI and a vTPM, the same CPUs and memory, and one network adapter per VMware adapter on the switch and VLAN named in the plan.
- Disk copy: one computer receives disks as VHDX files and shows its address, certificate thumbprint and a one-time pairing code; the machine being moved sends its disks through Volume Shadow Copy while it keeps running. The connection only works with the exact certificate typed in.
- The Disk converter (Alt+7) reads sparse and stream VMDK, VHD, VHDX (including differencing disks), qcow2 and raw, reads only allocated areas, and writes seven output formats.
- Hyper-V hosts are read over CIM without the Hyper-V module, and their VMs get the same readiness, plans, waves and runbooks as VMware VMs.
- Every step that changes something asks you to type the VM or computer name first. Credentials, pairing codes and passwords stay in memory and are never logged or saved.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime.
- Moving to Hyper-V runs on the Hyper-V host. Sending a machine's disks and reading physical disks need the application to run as administrator.
- These moves have been tested against simulators, synthetic data and test disks, not yet against real vCenter, Hyper-V, HyperCore, Nutanix or Proxmox hosts. Try a test VM first.
- Azure and Amazon EC2 remain planning targets only.
