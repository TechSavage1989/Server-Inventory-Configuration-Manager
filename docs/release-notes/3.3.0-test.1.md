# Server Inventory and Migration Manager 3.3.0-test.1

First test build. It is offered only to installs that ticked Also offer test builds in Help > Settings > Updates; stable installs never see it. It contains everything in 3.2.39 plus a reworked migration interface and VM consoles inside the app.

**Highlights**

- The migration screens are simpler: no header bar, a slim status bar at the bottom, a status track with the next step for every VM, and plain-language explanations with fix buttons beside each error.
- Open a VM's console from the app for VMware, Hyper-V, Proxmox VE, Nutanix AHV and Scale HyperCore, with special keys, paste as typing that works on sign-in screens and file transfer where the platform allows it.
- To go back to stable builds, untick Also offer test builds in Help > Settings > Updates; the newest stable release is then offered.

**Migration interface**

- Tool lists show each tool's name and one line; where it runs, what it works with and when to pick it are under About this tool.
- New migration has a sortable VM table, step summaries you can click to go back, saved defaults per customer and a rolling conversion option for VMware hosts converted to Hyper-V one at a time.
- Discovery can start a migration with the VMs it shows. Migration plans show a wave-by-wave Ready to cut over check (copies, failures, tests, recent syncs and SQL Server or domain controller findings).
- An activity strip under the tabs counts what is moving now on every screen.

**VM consoles**

- One console window for every platform, opened from VM pages, migration plan rows, All jobs and servers, New migration and Start VMs from copies. It has no power controls.
- Hyper-V consoles go through the host's own WMI interface with the signed Connect-HyperVConsole.ps1 script; nothing is installed on the host or in the VM.

**Requirements and limits**

- Same as 3.2.39: Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime.
- This is a test build. The new interface is covered by synthetic checks only, and the consoles have not yet been tried against real vCenter, Hyper-V, Proxmox VE, Prism and HyperCore hosts.
