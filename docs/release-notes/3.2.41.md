# Server Inventory and Migration Manager 3.2.41

VDDK copies of running VMs now work, plans, Discovery and New migration are easier to use, Sync now always answers, and vCenter sign-ins can optionally be remembered.

**Highlights**

- VDDK copies of running VMs now work: the application lets VDDK load its own plugins, which fixes error 16053 when a round started VDDK.
- Sync all now and Sync selected now always say what they queued and why a plan is waiting, and a plan waiting for its vCenter sign-in offers Sign in and sync right there.
- Remember sign-ins on this computer (off by default, in Help > Settings) keeps vCenter, ESXi and guest administrator sign-ins sealed for your Windows account so plans carry on after a restart.

**Migration plans and All jobs and servers**

- Sync now answers at once with the VMs it queued, the VMs it left alone and why, and the plan's waiting reason.
- A plan that waits for a missing inventory or sign-in shows Sign in and sync in the plan itself.
- A seeded VM or job whose round runs shows Syncing with its progress, whether or not it is overdue; Behind is only an overdue copy with no round running.
- Saving or creating a plan no longer waits for another plan's copy to finish.
- A VM whose copy round is running shows Syncing with its progress.

**Discovery and New migration**

- Once an inventory is open, Discovery's connection sections fold into one line that opens again with a click.
- New migration no longer redraws itself while you read it, so Show why stays open.
- The guest administrator account panel: the button no longer overlaps the password box, one click or Enter is enough, the name is filled in, and the password is remembered when Remember sign-ins is on.
- Obvious hints were removed, and ticking rows no longer moves the rest of the layout.

**VDDK and errors**

- VixDiskLib loads its own plugins (diskLibPlugin.dll and vddkVimAccess.dll) from the VDDK bin folder, which fixes error 16053 (VIX_E_DISK_SUBSYSTEM_INIT_FAIL) on hosts where the folder check passed but rounds failed.
- Help > Settings now names any DLL a VDDK folder needs that is missing from the folder and from System32, and points to the Visual C++ 2015-2022 x64 runtime when that is what is missing.
- VixDiskLib's own messages are written to VMware\VDDK\Temp\vddk.log, and a VDDK start, connect or open failure names the step that failed and that log.
- Long errors in Migration plans, All jobs and servers and the transfer list show one line with a Details link that stays open across refreshes.

**Remembered sign-ins**

- Off by default. When on, each sign-in is sealed with Windows DPAPI for the current Windows user in Settings\vcenter-signins.json; the page sees servers and user names only. Forget or unticking removes it, and a password the server refuses is forgotten at once with a notice.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime. The Linux agent needs x86-64 and systemd.
- Not yet field-tested: the VDDK log against a real VDDK, remembered sign-ins and automatic plan sign-in after a restart against a real vCenter.
