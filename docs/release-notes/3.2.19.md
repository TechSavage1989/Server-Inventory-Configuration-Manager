# Server Inventory Configuration Manager 3.2.19

Printer migration fix. Restore, reports, update validation and settings are unchanged apart from the PrintBRM checks below.

**Highlights**

- Print servers with no shared printer now get a printer migration export when the Print services export is selected.
- Collection now warns when PrintBRM does not write the export or reports an error, instead of finishing silently without it.
- Printer restore no longer depends on English PrintBRM messages, so it works the same on non-English Windows.

**Details**

- Earlier versions ran PrintBRM against the server by name. Windows reports success but writes no file when no printer on the server is shared. The collector now backs up the local print spooler directly.
- Packages collected with earlier versions from such servers have no printer export; collect again with 3.2.19 before a printer migration.
- The PrintBRM output is kept in 08-Role-Specific\Print-Server\PrintBRM-Export.log in each package.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime. Restoring needs administrator rights.
- A matching SHA-256 is integrity validation, not publisher signing.
- Validated on hosted Windows Server 2025 with the Print Server role and an unshared printer: the earlier method writes no export, the collector now does, and printers restore from it. Restoring onto a different server and Windows Server 2012 and 2012 R2 have not been validated.
