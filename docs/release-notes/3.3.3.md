# Server Inventory and Migration Manager 3.3.3

A server's roles can move live from the old server, you choose exactly what to restore or move, and domain controllers get their own guided move.

**Highlights**

- Restore from: Another server, live reads the old server's roles over PowerShell remoting, copies them to the new server and restores them there, with nothing installed on either server.
- What to restore and What to move list every category with Select all and Select none, and nothing is ticked for you.
- New Move a domain controller tool: builds and promotes a new domain controller from an existing one, moves the FSMO roles, can take over the old address and retires the old one.

**Move a server live**

- In the Restore tab, choose Restore from: Another server, live, type the old server and choose the new one (this computer or another).
- Look at the old server lists what it has per category; Copy what I picked carries only those items, and a second copy sends only what changed.
- Stop the sites on the old server stops its IIS sites at cutover; Start them again is the way back; Finish removes both copies.
- New migration offers A Windows server's roles, live from the old server or from a saved package, and hands off to the Restore tab.

**Choose what to restore**

- Package restores tick each chosen category's default items once the package is checked; group policy, registry and security policy items stay unticked.
- A live move reads only the items you picked, including the IIS backup only when IIS is picked and certificates only when chosen.

**Move a domain controller**

- Find it under Migration and replication, or pick A domain controller in New migration.
- Each plan chooses whether the new domain controller takes over the old address (the default) or keeps its own and clients are repointed.
- Steps run in order: build, promote, move the FSMO roles, then demote and clean up the old domain controller.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime.
- Linux replication, ReFS volumes and VMware copies made without VDDK still read all used data each round.
- Not yet field-tested: a live move between two real servers, promotion, FSMO transfer, demotion and the address swap on a real domain.
