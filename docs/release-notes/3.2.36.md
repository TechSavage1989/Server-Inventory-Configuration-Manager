# Server Inventory and Migration Manager 3.2.36

Migration release. Cutover now carries each VM's IP settings over automatically, with nothing run inside the old VM. A new guided flow takes a migration from choosing the VMs through to live status. Sending disks and receivers work again on hosts with several networks, and jobs survive receiver restarts. Collection, reports, restore and settings are otherwise unchanged.

**Highlights**

- Cutover powers the old VMware VM down, disconnects its adapters and fixes the new Hyper-V VM up by itself: the recorded IP settings, gateway and DNS are put back, VMware Tools is removed and Windows is activated, with nothing run inside the old VM.
- New migration is one guided flow from choosing the VMs to live status, and plans, waves and batches can be changed in bulk or by dragging. Rolling conversions can reuse the existing ESXi hosts one at a time.
- Fixed: Send disks refused every receiver thumbprint, the wrong receiver address could be copied, replication jobs stopped when a receiver restarted, and a stalled cutover could freeze with no error. Install and restart now says why when an update did not install.

**Moving VMs**

- No-touch cutover: in Move VMs, remote Hyper-V moves, migration plans and New migration, the new VM is reached through PowerShell Direct once it starts. Its adapters are matched by MAC address and the static IP settings recorded from vCenter are put back, with a rollback saved first. Hidden VMware adapters and VMware Tools are removed, offline data disks are brought online and Windows is activated. The guest administrator account is typed once and kept only in memory. If the fix-up cannot finish, Fix up now shows the reason.
- VMware Tools on the moved VM: its uninstaller refuses to run outside VMware, so when it does, the fix-up and Remove VMware Tools turn Tools' own services and drivers off instead and remove the hidden VMware display, mouse and system devices. Every value is saved first, and storage and network drivers are left alone. This stops the VMware display driver from blocking remote-control tools such as ScreenConnect.
- Readiness: on Hyper-V, static IPs and virtual TPMs are now information, since cutover handles them. Review items can be acknowledged per VM or with Acknowledge all, so Check readiness can turn green. Blocked VMs can never be acknowledged.
- New migration (the first tool in Migration and replication) runs as one sequence of screens (What, Where, How, When, Review, Status). It shows only the options for the chosen way of moving, and starts and follows a migration plan. Plans can also run from an admin computer to another Hyper-V host or cluster, and moves to HyperCore, Nutanix AHV and Proxmox VE are set up inside the same flow.
- Move VMs copies past a quiesce delta instead of reporting a false snapshot chain, reads datastores that ignore range requests, can consolidate disks, and shows live progress.
- Suggest waves groups VMs by role and risk instead of putting everything in two waves. The wave board supports dragging, splitting, merging and bulk moves, and batch Prepare runs on many VMs after you type how many.
- Migration scenarios: plan a rolling conversion of the existing hosts one at a time, with the new cluster's size, reusable storage and stages filled in from the VMware data.
- Every folder and file field in the migration and conversion tools has a Browse button.

**Replication and receivers**

- All jobs and servers shows many servers in one console and acts on them together. Replication can send to this Hyper-V host without a receiver being set up first.
- Send disks accepts thumbprints with or without colons. The receiver lists its default-route address first, Copy all includes the other addresses, and a pasted block picks an address that answers.
- A receiver started from the window keeps its certificate and pairing code across restarts and starts again when the application opens, so jobs carry on. A job that cannot reach its receiver waits and retries.
- A round that makes no progress for 5 minutes is stopped and the next round resumes, and the job shows how long it has been idle and which phase it is in. A cutover retries its final round up to three times with the services still stopped, Cancel cutover rolls a running cutover back, and an agent that restarts during a cutover starts the stopped services again.
- The window no longer freezes while a receiver verifies a finished copy. A receiver that cannot start because an older copy of the application holds its port offers to close exactly that copy.
- Jobs keep the receiver's other addresses and switch to one that answers with the same certificate and code. Check receiver runs from the server being replicated.
- Start VMs from copies: a test VM starts not connected and warns before joining an external network, Production fills the switch and VLAN from the VMware data and says where they came from, and Finish cutover by hand marks a job cut over without changing the server.

**Reports and interface**

- Discovery and readiness reports are interactive HTML pages, and are also written as Word and PDF documents with clickable contents and links.
- Every tab and tool fills the whole window, and text fits more on small screens.
- The browser right-click menu and accidental text selection are gone from the interface. Fields, logs and values can still be selected and copied.

**Updates**

- Install and restart records the outcome of every attempt. If an update did not install, the next start shows the reason, a manual way to install it and Try again. Locked files are retried, the installed file is checked, and slow first starts get more time before a rollback. This applies to updates from 3.2.36 onward.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime. The Linux agent needs x86-64 and systemd.
- Not yet field-tested: the automatic fix-up through PowerShell Direct into a real new VM (including MAC matching and VMware Tools removal on Hyper-V), rolling conversions, the receiver's saved identity and auto-start on a real Hyper-V host, and remote Hyper-V hosts and clusters.
