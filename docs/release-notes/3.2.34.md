# Server Inventory and Migration Manager 3.2.34

Endpoint protection release. The replication agent takes shadow copies through the Windows backup interface instead of PowerShell, so security software such as SentinelOne no longer treats it as ransomware. Everything the application runs is signed. Collection, reports, restore, file share migration, VMware moves, the disk converter and settings are otherwise unchanged.

**Highlights**

- The replication agent no longer runs PowerShell or deletes shadow copies: it uses the Windows backup interface, and Windows removes each snapshot by itself when the round ends.
- If security software or a crash stops the agent, the console now says so, Windows restarts it, and the job carries on where it stopped.
- Every release, and every script the application runs except the protected inventory collector, is signed; a guide lists the exclusions for SentinelOne, Defender and CrowdStrike.

**Details**

- Shadow copies are non-persistent backup sets of type copy: they leave application backup history alone and are freed even if the agent is ended.
- An internal error during a round now fails that round, with details in the agent's log folder, instead of stopping the agent.
- The agent records whether its previous run crashed or was ended from outside, raises an alert (Application event 1004) and tells the console.
- Windows restarts the agent service after every failure. Upgrade an agent by running Install agents for it again; its jobs keep their copies.
- When an agent does not answer, the Replication tab says why in plain words and marks its jobs as last known.
- See docs/EDR-EXCLUSIONS.md in the repository for exclusions and for removing shadow copies a 3.2.33 agent may have left.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime. The Linux agent needs x86-64 and systemd.
- Not yet tested against SentinelOne on a real server; add the exclusions in the guide before the first round.
