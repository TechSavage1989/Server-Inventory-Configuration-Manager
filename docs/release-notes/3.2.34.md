# Server Inventory and Migration Manager 3.2.34

Migration and replication now live in one place with a guided walkthrough, live progress and receivers that find each other on the network. The replication agent no longer looks like ransomware to security software such as SentinelOne, and everything the application runs is signed. Collection, reports, restore and settings are otherwise unchanged.

**Highlights**

- One Migration and replication area holds every tool, says where each one runs and which systems it works with, and a guided migration walks any source to any target step by step.
- The replication agent takes shadow copies through the Windows backup interface instead of PowerShell, so security software no longer treats it as ransomware, and everything the application runs is signed.
- Receivers can be found on the network and paired by approval, transfers show live progress, speed and time left, and a replication job can be changed with one Save, even while it is paused.

**Migration and replication**

- The tabs are now Discovery, Collection, Report Viewer, Restore and Migration and replication. VMware and Hyper-V discovery moved to Discovery; old tab names still open the right tool.
- Guided migration builds the steps for the chosen source and target, names the computer each step runs on, checks the state as you go and keeps a step closed when it would run on the wrong computer or without enough space. Ways to do this lists only the methods that fit.
- Every tool card and title says which sources and targets it works with, and whether it is agentless, agent-based or run inside the source, live or offline.
- Senders find receivers on the same network (or one typed computer on another subnet). Pairing by approval shows a six-digit check number on both sides and hands the pairing code over only after you allow it on the receiver.
- The receiver lists connected senders and every copy with progress, speed and time left; Send, Move and replication jobs show theirs. Summary tiles are buttons that filter the list and say what to do next.
- On a Hyper-V host, copies and the receiver default to the host's virtual hard disk folder, Move VMs offers Cluster Shared Volumes with free space and can add the VM to the failover cluster at cutover.
- Start VMs from copies refreshes by itself, ticks finished disks, explains why Create the VM is disabled, follows the boot disk's firmware, fills processors, memory and adapters from the source computer, names test VMs and shows a checklist and the next step.
- The initial copy is marked: the job says "Initial copy complete, ready to cut over" with Test failover and Cut over buttons (Application event 1005).
- Windows activation: Record settings saves the license channel, Check what needs fixing gives the fix, and Activate Windows can install a key, including Microsoft's published AVMA keys.
- Change on a replication job works while it is paused or mid-round: the agent stops the round, applies the change and starts again where it stopped. Greyed-out buttons say why they are off.

**Endpoint protection**

- The agent no longer starts PowerShell or deletes shadow copies. Shadow copies are non-persistent backup sets of type copy: they leave application backup history alone and Windows frees them when the round ends, even if the agent is ended.
- If security software or a crash stops the agent, it raises an alert (Application event 1004), the console says why, Windows restarts the service and the job carries on where it stopped. An internal error fails only that round.
- Every release, and every script the application runs except the protected inventory collector, is signed. See docs/EDR-EXCLUSIONS.md in the repository for SentinelOne, Defender and CrowdStrike exclusions and for removing shadow copies a 3.2.33 agent may have left.
- Upgrade an agent by running Install agents for it again; its jobs keep their copies.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime. The Linux agent needs x86-64 and systemd.
- Not yet field-tested: SentinelOne on a real server (add the exclusions before the first round), receiver discovery across real switches and VLANs, adding a VM to a real failover cluster, and Activate Windows with AVMA on a real Datacenter host.
