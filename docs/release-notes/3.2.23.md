# Server Inventory and Migration Manager 3.2.23

Migration release. Collection, reports, restore, update validation and settings are unchanged.

**Highlights**

- Migrate can now choose the new folders with the Windows folder picker: Browse on a share, or Choose a folder for all to put every selected share in its own folder inside one folder.
- Each new share's top folder now gets the old top folder's permissions, including those it inherited on the old server, so access works the same after the move.
- Cutover now opens each new share through its network path to confirm it works, and marks any share that does not open for attention.

**Details**

- The folder picker includes Make New Folder. Folders that don't exist yet are created when copying starts, and a folder that already holds other files is still refused.
- Choose a folder for all names each folder after the new share name. Shares you have not ticked keep their folder.
- Folders inside Windows, Program Files, ProgramData or the user profiles folder are refused, so a mirrored copy can never damage them.
- The top folder's permissions are written to that folder only. Later copies still bring over only what changed.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime.
- A matching SHA-256 is integrity validation, not publisher signing.
- Validated on hosted Windows with the runner as both servers. Not yet checked against a separate old server, or on Windows Server 2012 or 2012 R2.
