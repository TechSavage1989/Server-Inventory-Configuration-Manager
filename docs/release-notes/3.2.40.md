# Server Inventory and Migration Manager 3.2.40

Fix release. Help > Settings now accepts a genuine VDDK folder that 3.2.38 and 3.2.39 refused on some hosts. Everything else is unchanged from 3.2.39.

**Highlights**

- Help > Settings accepts genuine Broadcom VDDK folders again: each DLL's embedded signature and the vixDiskLib version are checked from the files themselves.
- A VDDK folder whose files are not signed by Broadcom or VMware, or are older than 7.0.3, is still refused, and the message now gives every reason.
- Nothing else changes: collection, reports, restore, migrations and settings work as in 3.2.39.

**VDDK**

- On some hosts Windows' own checks (WinVerifyTrust and the file version API) could not read genuine VDDK 8.0.3 files, so the folder was refused. The application now verifies each DLL's embedded Authenticode signature itself (the file hash, the signed attributes, the signature and a code-signing chain to this computer's trusted roots) and reads the version resource directly. If that check refuses a file, Windows' own check is tried next.
- A file that is not a program file (for example an online-only or blocked download) now says its size and first bytes, so it is easy to recognise.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime. The Linux agent needs x86-64 and systemd.
- Not yet field-tested: loading VDDK on the host where Windows' own checks failed, and VDDK reads against a real ESXi host and vCenter.
