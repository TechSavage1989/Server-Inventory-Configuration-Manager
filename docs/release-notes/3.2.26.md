# Server Inventory and Migration Manager 3.2.26

File share migration update. Inventory collection, reports, restore, updater security, and portable executable behavior are otherwise unchanged.

**Highlights**

- Choose Allow overwrite of an existing destination separately for each file share when migrating or synchronizing to a server that already has files or a share using the same name.
- Repeat copy operations to synchronize changes and deletions. Overwrite-enabled copies require typing the destination server name before running.
- Cutover can replace an approved existing share mapping and saves its prior path, settings, and share permissions before changing it.

**Details**

- The overwrite option starts off and stays off unless you select it per share. A changed choice requires checking the plan again.
- The normal copy continues to refuse nonempty unknown destinations and unexpected share-name conflicts.
- When overwrite is enabled, Robocopy mirror mode copies changed files and deletes files at the destination that are absent from the source. It does not create an automatic backup of file contents.
- The final cutover can replace an existing share pointing to another folder, disconnecting clients. The old share definition and its share permissions are recorded under the local migration work folder first; if creation of the new mapping fails, the application attempts to restore the old mapping.
- Windows administrative share names are not available as replacement targets. Clustered or scoped SMB shares are excluded from automatic remapping.
- SYSVOL, NETLOGON, and other Windows role-managed shares remain unselected by default and show additional warnings when selected. Replacing role-managed shares can interrupt Active Directory, Group Policy, and other services. Use role-specific recovery and replication procedures.
- A delta precheck estimates additional free space from files expected to copy rather than counting the full source size again.

**Requirements and limitations**

- Windows x64, Windows Server 2012 or later, Windows PowerShell 3.0 or later, and Microsoft Edge/Chrome 109 or later or the WebView2 Runtime.
- Tested using a disposable hosted Windows runner with synthetic shares, a repeated Robocopy delta pass, an occupied destination, and an existing share-name replacement. Live domain controller shares, clustered shares, production user sessions and two separate domain servers have not been validated.
- An exact SHA-256 checksum confirms downloaded bytes, not publisher signing. Never use this feature as a substitute for backup and a tested recovery procedure.
