# Server Inventory and Migration Manager 3.3.1

Discovery keeps one folder per server, and Build Hyper-V hosts can add converted hosts to an existing Hyper-V cluster.

**Highlights**

- VMware and Hyper-V discovery writes each server into one folder (VMware_server or HyperV_server) that is updated in place, instead of a new folder on every read or sign-in.
- Build Hyper-V hosts can join an existing Hyper-V cluster or take in standalone Hyper-V hosts, reading the existing setup so new nodes match it.
- In a rolling conversion, hosts still on ESXi wait as Still ESXi, and the page fills in suggested values with a reason for each without overwriting what you changed.

**Discovery**

- A folder already open for that server, including one chosen with Open a saved inventory, is reused.
- The inventory being replaced is kept in History inside that folder (newest 20).
- A sign-in the app makes by itself after a restart writes no folder or report.

**Build Hyper-V hosts**

- Step 1 asks what you are building: a new cluster from VMware, hosts added to an existing Hyper-V cluster, or a new cluster that takes in standalone Hyper-V hosts.
- Reading the existing cluster or host only reads (over WinRM): switches, VLANs, host adapters, iSCSI and Fibre Channel storage, live migration settings, nodes, quorum, networks and CSVs. Joining never creates a cluster.
- Read nodes sits in step 2 under the node names. Filled values are tagged Suggested (or Suggested: check it is free for addresses); values you change are tagged Set by you and are never filled again, even after another read.
- Next host to convert guides the first host still waiting.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime.
- Reading a real cluster, joining a real node and port matching on real hardware have not yet been field-tested.
