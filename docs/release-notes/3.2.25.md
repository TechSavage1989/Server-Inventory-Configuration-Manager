# Server Inventory and Migration Manager 3.2.25

Startup fix release. Collection, reports, restore, migration, update validation and settings are unchanged.

**Highlights**

- When the interface opens in the built-in window, the application now waits up to 3 minutes for Microsoft Edge WebView2 to start instead of 45 seconds.
- This fixes a false "The application interface could not open" message that could appear while the window was still loading behind it.
- The application log now records how long the built-in window took to start.

**Details**

- The built-in window is used when no private Edge or Chrome guest window can open, for example when policy turns off guest browsing.
- The first start after a new WebView2 Runtime is installed or updated can take more than a minute on a slow or freshly started server.
- If the window still does not start within 3 minutes, the message is shown and the late window closes itself instead of loading behind it.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime.
- A matching SHA-256 is integrity validation, not publisher signing.
- Validated on hosted Windows with WebView2 Runtime 157. The slow first start that exposed the problem is intermittent, so a passing run does not prove every slow start; the limit now leaves a wide margin.
