# Server Inventory and Migration Manager 3.2.33

Replication release. A new Replication tab keeps whole Windows and Linux servers copied to their new home every few minutes, with test failovers, scheduled cutover and failback, all managed from one console. The Disk converter can now prepare converted Windows disks for their new platform, send them to a host as a new VM, and copy disks of the computer it runs on. Running Hyper-V VMs can be copied and cut over like VMware VMs. Collection, reports, restore, file share migration, update validation and settings are otherwise unchanged.

**Highlights**

- Replication tab: install an agent on any Windows or Linux server, keep all of its disks replicated to a receiver every few minutes, run test failovers, then cut over when ready.
- Test failover on Hyper-V, HyperCore, Nutanix AHV and Proxmox VE: the app pauses at a whole recovery point, starts an isolated copy of the server, and removes it when the test ends while replication carries on.
- Disk converter: prepare a converted Windows disk for its new platform, send it to vSphere, Hyper-V, HyperCore, Nutanix or Proxmox as a new VM, or copy a disk of this computer (P2V).

**Details**

- Replication jobs read every volume from a new Volume Shadow Copy each round and send only changed 4 MB chunks, compressed if wanted and paced by a business-hours bandwidth schedule. No kernel driver is installed.
- NTFS change tracking reads only what changed between rounds, including files whose data was moved by a defragmenter, and a full comparison every six hours turns tracking off for a volume if it ever missed anything.
- Spanned, striped and mirrored dynamic volumes are read together from one shadow copy. Linux servers are read through LVM snapshots.
- The Windows agent installs as a service, pushed from the console with an account used only for that install. The Linux agent installs over SSH with a pinned host key. The console keeps agent keys encrypted for the current user.
- Cutover stops the services you list, copies the last changes, verifies every disk and can shut the source down. If any step fails the stopped services are started again and replication carries on. Failback is a new job that sends only what differs.
- Running Hyper-V VMs are copied through the application's own checkpoint, which is removed after every round, and cut over through the guest shutdown integration service.
- Each step that runs on a different computer is labelled, and the replication runbook and the VMware runbook are written as HTML and Word with check boxes that tick.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime. The Linux agent needs x86-64 and systemd.
- Agents, sending disks and reading physical disks need administrator or root rights.
- These features have been tested on CI runners, simulators and test disks, not yet against real Hyper-V, HyperCore, Nutanix, Proxmox or vSphere hosts. Try a test server first.
