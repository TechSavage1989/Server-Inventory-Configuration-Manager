# Server Inventory and Migration Manager 3.2.22

Migration release. Collection, reports, restore, update validation and settings are unchanged.

**Highlights**

- Migrate can now connect to the old server with another account: under Connect as, choose Another account and enter its user name and password.
- When the old server refuses access, the Connect as fields open so you can enter an administrator account of the old server.
- The password is kept in memory only, until you close the application or choose Start over, and is never saved or written to a log.

**Details**

- The account is used for every step that reaches the old server: reading its shares and permissions, checking the plan, copying, cutover, and making the old shares read-only or undoing that.
- Remote management uses WinRM, then DCOM with packet privacy. File access (the old server's administrative shares and Robocopy) uses a connection opened for each step and removed when the step ends.
- Type the user name as DOMAIN\admin or admin@domain. Connecting again to the same server with the same user name reuses the password you entered.
- Messages say what went wrong: a wrong password, an account that is not an administrator on the old server, or an existing connection to that server under another account (close File Explorer windows and mapped drives that use it, then try again).

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime.
- A matching SHA-256 is integrity validation, not publisher signing.
- Validated on hosted Windows with a synthetic local administrator account and the runner as both servers. Not yet checked with a domain account against a separate old server, or on Windows Server 2012 or 2012 R2.
