# Server Inventory and Migration Manager 3.2.39

Migration release. Cutovers can be rolled back in one click, copies of running Hyper-V VMs read only changed blocks, VMs with a virtual TPM can be moved, and you can opt in to signed test builds. Collection, reports, restore and settings are otherwise unchanged.

**Highlights**

- New Roll back tool and a Roll back button beside every cut-over VM: it shuts the new VM down, confirms it is off, reconnects the original and starts it again.
- Help > Settings > Updates has Also offer test builds. Stable stays the default and never installs a test build; opting in offers signed test builds, and unticking it offers the newest stable release again.
- Running VMs with a virtual TPM can now be moved through VDDK or copied at their cutover while shut down, and one migration plan can mix copy methods per VM.

**Moving VMs**

- Roll back: every cutover that creates a VM leaves a record. Rolling back never deletes the new VM, its disks or copies, and never starts the original before the new VM reads back as off. Domain controllers need their own tick box because of USN rollback. Ways of moving that cannot roll back by themselves (P2V, V2P, conversions, file shares, restore, a rebuilt host) list the steps.
- Hyper-V change tracking: copies of running Hyper-V VMs on Windows Server 2016 and later keep a reference point after each round, so the next round and the cutover read only the blocks that changed. Hosts or disks that cannot answer read all used data as before.
- Virtual TPM VMs: vSphere will not export a running VM whose own files are encrypted, so the round says so in plain words. Set up VDDK in Help > Settings, or choose Copy at cutover for that VM in its plan row or in New migration's Review.
- Production space and bandwidth: copies check free space before they take a snapshot or checkpoint and keep to their bandwidth limits and concurrency.

**Accounts**

- Every Windows account field starts with Connect as: My current sign-in, or A different account to type one. Where the current sign-in cannot work (PowerShell Direct, Linux over SSH, the old server of a file share move from an admin computer) the field says why.

**Discovery**

- Discovery and This server stay usable while a migration plan copies, and anything that must wait now says why with a link to what holds it.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime. The Linux agent needs x86-64 and systemd.
- Not yet field-tested: rollback against a real vCenter and Hyper-V cluster node, Hyper-V reference points and changed-block queries on a real host, VDDK reads of a real virtual TPM VM, and an offline cutover of one.
