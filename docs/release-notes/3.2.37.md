# Server Inventory and Migration Manager 3.2.37

Migration fix release. Copies of running VMware VMs no longer fail when ESXi refuses to read the running disk, receivers keep working after a reboot, and New migration absorbs Guided migration. Collection, reports, restore and settings are otherwise unchanged.

**Highlights**

- Fixed: copying a running VMware VM failed every round with "the server answered 500 Internal Server Error" for its flat.vmdk. When ESXi refuses the running disk, the copy now reads the round's snapshot through vSphere's own export.
- A receiver can keep receiving after a reboot and while the application is closed, as a local Windows service on the receiving computer.
- New migration now holds the Guided migration steps, nothing is cut off on small windows, and VMware and Hyper-V discovery can choose where its reports are saved.

**Moving VMs**

- Running VMs: when the datastore refuses a disk the VM holds open, each copy round reads its own replication snapshot through vSphere's export of it. Later rounds stay delta passes of the same copy: they read the disk's used data again but write only what changed. The computer doing the copy must reach the ESXi host that runs the VM on port 443. Its certificate is trusted through Windows or the thumbprint vCenter gives for it.
- The network map uses a plan's switch only when the host has it, otherwise a switch with the same name or the only external switch, with the port group's VLAN. A missing switch now stops the plan at Where and Review. On a cluster, only switches every running node has are offered.
- VMware Tools on a moved VM: when its uninstaller refuses to run outside VMware, its services, drivers, driver packages, installer entries and program folder are removed by exact name after each is saved. Storage, network and Windows' own mouse drivers are kept.
- Use the account I'm signed in with fills the guest administrator name, and Use this account no longer reports a false missing-account error.

**New migration and discovery**

- Guided migration is folded into New migration: its How screen shows the steps for every way that continues in its own tool, each with the computer it runs on and live checks. Old Guided migration links open New migration.
- Every tool and every New migration screen fits at 1008x690 and larger without clipped content, and Back and Next stay in view.
- Encrypted VMs: migration plans now refuse only VMs whose disks are encrypted (a VM encrypted only for its virtual TPM copies as it is). New migration flags such VMs in What and offers Decrypt N VMs inside Review, with live progress; decrypting may run up to 24 hours per VM.
- Discovery > VMware and Hyper-V has Save discovery reports in, with Browse. It uses the same output folder as This server, so a fresh install no longer falls back to the Desktop.

**Confirmations**

- Confirmations are now a tick box by default instead of typing names. Help > Settings can switch to a dialog, typed names or no confirmation.

**Receivers**

- Keep receiving after a reboot and while this application is closed installs the SIMMReceiver service on the receiving computer only, with administrator rights. The window receives while it is open and hands over to the service when it closes, with the same folder, port, certificate, pairing code and failover holds. Unticking removes the service, its firewall rules and its folders.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime. The Linux agent needs x86-64 and systemd.
- Not yet field-tested: reading a running VM through the snapshot export on a real ESXi host and through vCenter, the receiver service across a real reboot, and cluster switch checks across real nodes.
