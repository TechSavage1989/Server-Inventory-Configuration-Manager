# Server Inventory and Migration Manager 3.2.30

Full VMware discovery and the first step of the move engine. Reading vCenter or ESXi now records every host in detail along with licensing, clusters, resource pools and distributed switches, and the VMware tab can prepare a source VM and write the runbook as a Word document. Collection, reports, restore, file share migration, update validation and settings are otherwise unchanged.

**Highlights**

- VMware discovery now records each host as vCenter reports it: hardware, serial number, BIOS, network adapters, switches, VMkernel ports, storage adapters and devices, NTP, services, installed VIBs, alarms and certificate expiry, plus licenses and their assignments.
- A new Hosts and licenses panel and VMware discovery report list every host and license and flag expiring licenses or certificates, alarms, hosts in maintenance and missing NTP.
- The runbook can be opened in Word, and Prepare source can remove snapshots, shut down the guest, remove the virtual TPM and decrypt an encrypted VM, one VM at a time after you type its name.

**Details**

- License keys are masked to their first and last groups in the app, reports and CSVs.
- Clusters record EVC mode, HA admission control and host monitoring, DRS automation and vSAN; resource pools, vApps and distributed switches are listed with their settings.
- Ten new CSVs cover host network adapters, virtual switches, VMkernel ports, storage adapters, storage devices, services, software packages, licenses, resource pools and distributed switches.
- vCLS agents, the vCenter appliance and nested ESXi hosts are shown as not moved; guest-managed VMware Tools, backup-software snapshots and domain controllers get clearer guidance.
- Prepare guest can save BitLocker recovery keys to the output folder and suspend protection before a move.

**Requirements and limits**

- Windows x64, Windows Server 2012 or later, with Microsoft Edge or Chrome 109 or later, or the WebView2 Runtime.
- Prepare source is the only step that changes vSphere and asks before every VM. Decrypting has been tested only against the VMware simulator, which has no encryption, and the installed VIB list has not yet been read from a real host; check both on your own vCenter first.
- Disks are still not converted or copied; use the usual tool for your platform.
